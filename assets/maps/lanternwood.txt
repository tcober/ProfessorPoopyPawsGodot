; LANTERNWOOD - 56x51 tiles (896x816 px): Fuji's hometown, REBUILT 2026-07-28
; from a flat snow field into a NARSHE-style terraced mining town (FFVI).
; Verticality in this engine is AUTHORING, not a system, so all of the depth
; here is map structure. FIVE walkable levels, FOUR cliff bands, THREE band
; heights:
;
;   rows 2-11   LEVEL 5  - the library alone, backed against the pines
;   rows 11-14  BAND A   - B, FOUR rows: the big back wall. Stair T (cols 30-31)
;   rows 15-22  LEVEL 4  - two cabins
;   rows 22-23  BAND B   - C, TWO rows. Stair S (cols 12-13)
;   rows 24-31  LEVEL 3  - a cabin, and the SKATING RINK (O) on the east flank
;   rows 31-33  BAND C   - X, THREE rows. Stair s (cols 26-27)
;   rows 34-40  LEVEL 2  - Fuji's family home, the pond
;   rows 41-42  BAND D   - C, TWO rows. Stair S (cols 24-25)
;   rows 43-48  LEVEL 1  - the gate, the MOOT HALL, and the harbour lane
;   rows 49-50  THE GATE MOUTH - two road cells cut through the pine border
;   cols 46-55  THE COVE (rows 41-50) - open water, the pier and the berth
;
; LEVEL 1 IS SIX ROWS DEEP, NOT FIVE, AND THAT IS NOT COSMETIC (2026-07-29).
; The moot hall is FOUR rows tall on this terrace, so at five rows the harbour
; lane past it was ONE cell of headroom at cols 33-39. An NPC is a StaticBody2D
; with a 12x8 box in a 16px cell: anybody standing in a one-cell lane is a WALL,
; not a squeeze. Mayor Hollis sealed the pier off completely just by walking out
; of his own door, and the player could reach him and then have nowhere to go.
; Six rows makes the lane two cells the whole way and there is now NO single
; walkable cell anywhere on the map whose removal isolates the pier. If a
; building is ever added to a terrace, check that number again: the rule is
; footprint rows + 2, never footprint rows + 1.
;
; THE HARBOUR AND THE MOOT HALL (2026-07-29). Lanternwood is on an ocean-locked
; island and its map had never once shown the ocean, which is a strange thing
; for a town whose only way off the island is a boat. So the east end of LEVEL 1
; is a COVE now: sea (~) from col 46 out to the map edge and from BAND D down
; past the south border, so the water runs off-screen on two sides and reads as
; ocean rather than as a pond. BAND D stops at col 45 and the terrace's east end
; is a headland over the water; the sea shores against snow, which the driver
; already draws as an ICE-SHELF LIP (_lip_band's "snow" pair) - the one shoreline
; treatment a winter town wants and it was already written.
;
; Sea is SOLID, so the cove seals the map's east and south borders on its own -
; no pine border needed out there, and the enclosure lint passes because the
; only walkable border cells are still the two gate-mouth road cells.
;
; THE PIER (=) is a 7x2 WALKABLE deck of terrain class "dock" -> render class
; `bridge`, which is in the driver's WATERC family, so no coastline forms
; between the deck and the water it stands over. It is baked Tier-1 as ONE
; opaque town_dock blit (the town_trestle/cliff-face idiom): a rail on a
; walkable deck cell can never be upper-layer art, and the deck is walked along
; its length so nothing autotiles it. Its west end butts the shore at col 45,
; which is why LEVEL 1 now reaches col 45 and not 44.
;
; THE BERTH (b) is 6x2 SOLID cells of terrain class "berth" -> render class
; `sea`, i.e. they paint as animated open water and the LAUNCH sits on them as
; a Tier-3 y-sorted 8-frame prop. Two reasons it is sea and not more dock:
; a boat moored on painted planks reads as a boat in a car park, and a body
; standing on the deck's south row hangs ~11px of sprite over the cell below it
; - which here is the launch, y-sorted SOUTH of the body, so the hull swallows
; the overhang for free. That is the mask-band problem solved by composition.
;
; THE MOOT HALL (v/V) is the town council hall, on a cabin's 5x4 footprint at
; cols 35-39 with its D cell one row south at the x-centre (col 37) - the same
; roof/body/door arrangement as every cabin, so nothing new is needed of the
; kit. It is on LEVEL 1 on purpose: the mayor sits between the gate and the
; water, which is where a harbour town's clerk belongs, and it puts him exactly
; where the player is standing when the defence of the lower street ends.
; slime_b moved out of (36,44) because the hall now stands on it - see its anchor.
;
; THE SOUTH GATE (2026-07-29). Until now LEVEL 1 was an open snow field: the
; lane ran three cells past the stairs, stopped, and the exit trigger floated
; invisibly on it. Nothing said "this is the way out", so a fight in the lower
; street kept ending with the player on the overworld by accident. Now the lane
; is TWO cells wide the whole way down, a three-cell pier stands either side of
; it (N/n west, M/m east - two walkable crowns over a solid base, the conifer
; idiom, each with a bracket lamp aimed into the lane), and the road runs OUT
; through a two-cell cut in the pine border. exit_south sits in that mouth, so
; leaving is a thing you walk INTO rather than a thing you wander onto. The road
; reaching the map's last row is why lanternwood.gd walls just past the south
; edge, the same as both Alembic maps.
;
; EVERY BAND STAIRCASES. Bands A/B/C each shift their top row by one between
; column segments, which is the difference between rock and a stripe: two
; uniform 2-row bands read as ONE cliff drawn twice, which is exactly how the
; first draft of this map failed. Each column still carries exactly one run of
; its band's height, which is all stamp_columns cares about.
;
; A cliff run must be EXACTLY as tall as its char declares - C=2, X=3, B=4 -
; and a stair must be as tall as the band it pierces (S=2, s=3, T=4). The face
; art lands on a run's TOP cell, so a short run paints a rock wall over the
; WALKABLE cell below: a wall you walk through, which nothing in _check_art.py
; catches. stamp_columns asserts the height for exactly that reason, and
; TileScene.assert_reachable then proves every door and anchor is still
; walkable-to from the gate - with five levels and four chokepoints, one
; mistyped band cell would otherwise strand a whole terrace silently.
;
; THE RINK (2026-07-29) replaced a chasm-and-trestle that used to cut the east
; flank. The rift never read as a rift no matter how its face was drawn: a
; 2-row band of dark in flat top-down is a wall, and the trestle across it
; looked like a wooden panel set into one. Verticality here is authoring, and
; authoring an absence is the one thing it is bad at - a hole is defined by
; what you CAN'T see. So the east terrace is open ground now, with the town's
; rink on it (O - the same frozen_pond treatment as the little pond by Fuji's
; home, at 8x4 and SKATED, so it reads as somewhere the town goes) and a lamp
; either side. Nothing is lost that was working.
;
; A stair is a 2-wide walkable block spanning ALL of its band's rows with a road
; cell directly north and south, so the trail painter's ribbon connects through
; it (stairs render terrain class "road"); the opaque town_stairs blit covers
; the ribbon afterwards. Cabins sit on LEVEL rows only - a footprint straddling
; a band row would bake its contact shadow onto a cliff face.
;
; Tiled by assets/_gen_tileset_lanternwood.py on the shared OverWorld driver;
; collision/markers by scene/lanternwood.gd. Cabins span roof+body char pairs
; (all solid, footprint bbox + collision only - the whole cabin is a Tier-3
; y-sorted 8-frame sheet whose windows breathe). Standalone conifers alternate
; Y/y (small) and P/p (old-growth), where the CASE means crown vs trunk: the
; upper three rows are WALKABLE boughs a body stands among and only the bottom
; row is solid, so you can walk behind a spruce instead of bouncing off a 4-row
; wall. Same idiom as the lamps, which are L (walk, the mantle overhangs head
; height) above l (solid, the post). NOTE the old anti-merge trick is gone with
; it: two spruces authored edge-to-edge now FUSE into one component and one
; stretched sprite, so _gen_tileset_lanternwood.py asserts every component is a
; clean 2x4 with exactly its bottom row solid.
;
; THE LIBRARY (k/K) is the one enterable door in town: its D cell TRAVELS to
; scene/library.tscn. Every other banner is announce-only.
